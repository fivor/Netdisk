# 网盘资源转存项目 · 最终实施方案

> 来源：资料库在线文档 <https://www.workbuddy.cn/space/d/Dsh5fNQFezjO7JbC3Rxg53>（v2.0 终版，2026-09-15）
> 本文件为该方案导出的本地副本，存放于 `G:\Netdisk`，供开发阶段随手查阅；线上文档为准。

**目标**：用户粘贴一个网盘分享链接（百度 / 夸克 / 阿里，可带提取码），网站自动把资源转存到你自己的网盘账号，并返回新分享链接；同时提供「文件落地家里电脑 → 小圈子直接下载」的中转下载站。

**定位**：仅小圈子自用；分步推进，最终覆盖全部转存方向。

**已有资源**：百度会员、夸克会员、阿里云盘账号、2TB 本地硬盘、上海移动家宽（下行快 / 上行 30~50Mbps / 无公网 IPv4）。

**版本**：v2.0 终版（2026-09-15）。整合调研版与全部修订结论，替代旧版结构；调研原文已备份至工作区 `网盘转存项目方案-调研版备份.md`。

## 一、项目定位与关键决策

### 1.1 需求拆解

| 维度 | 说明 |
|---|---|
| 输入 | 网盘分享链接（百度 / 夸克 / 阿里，可能带提取码） |
| 输出 | 目标网盘的新分享链接 + 提取码（内容相同）；或中转站直链下载 |
| 账号 | 全部用你自己的账号：百度会员 / 夸克会员 / 阿里云盘 |
| 本地 | 2TB 硬盘（热门缓存）、家里电脑（部署主机） |

### 1.2 四项关键决策（已确认）

| 决策项 | 结论 | 对方案的影响 |
|---|---|---|
| 是否对外开放 | 仅小圈子自用 | 合规投入降到最低：入口加密码即可，不需要审核 / 举报机制；按几十人低并发设计 |
| 转存方向 | 分步推进，最终全部实现 | 按「同平台直转 → 跨平台中转 → 中转下载站」三步走（见第七节） |
| 技术验证 | 先 PoC 再开发 | 阶段 1 设 6 项验证点（见第八节），全部有结论后再写正式代码 |
| 部署环境 | 家里电脑 + Cloudflare Tunnel | 新增「中转下载站」能力；移动家宽无公网 IPv4，Tunnel 是正确选择；上行带宽是该能力的物理天花板 |

## 二、核心结论（先给答案）

1. **转存引擎优先级**：同平台直转 → 跨平台秒传尝试 → 流式中转 → 目标盘离线下载。能不落盘就不落盘，能不动家里带宽就不动。
2. **认知修正**：跨平台「零落盘纯秒传」不成立——三家秒传所需哈希互不兼容，源盘接口凑不齐目标要的哈希（详见第三节矩阵）。秒传降级为「流式中转过程中的加速器」。
3. **技术底座**：OpenList（AList 社区分叉）当转存引擎 + FastAPI 自研编排 + SQLite 任务库，Docker Compose 一键部署，不引 Celery/Redis。
4. **原始思路「先下载再上传」升级为「流式中转」**：数据边下边传不落盘，2TB 盘从「必备缓存」降级为「热门文件缓存」。
5. **工作量重心**：编排逻辑 + Web UI + 账号运维，而非网盘接口逆向——底层轮子社区都有现成的。

## 三、四条转存路径

### 路径 1：同平台直转（首选，秒级 / 零成本 / 不落盘）

- 原理：调用网盘「保存分享」接口，本质是服务器端转存，数据完全不过本地。
- 适用：百度→百度、夸克→夸克、阿里→阿里。
- 依赖：有效 Cookie（百度 / 夸克）、OpenAPI Token（阿里）。

### 路径 2：秒传（加速器，命中率决定收益）

- 原理：提交文件哈希，若目标盘云端已存在同内容文件则瞬间完成、无需真实传输。
- 实现策略：任务开始时用已知哈希先试一次秒传，命中即终止；未命中自动降级路径 3。
- 关键约束（v2 修正）：三家哈希体系互不兼容，见下表。

#### 3.1 哈希与秒传矩阵

| 平台 | 秒传所需哈希 | 源分享/文件接口可提供 | 作为目标盘的结论 |
|---|---|---|---|
| 百度 | 整文件 MD5 + 前 256KB MD5 + 大小 | MD5、大小 | 源是夸克时只缺「前 256KB MD5」，可轻量拉取补算后尝试秒传；源是阿里时整缺，直接流式 |
| 夸克 | MD5 + SHA1 + 大小 | MD5、大小（SHA1 待实测） | 缺 SHA1，流式中转时补算 |
| 阿里云盘 | SHA1（支持前 1KB SHA1 预检） | SHA1、大小 | 源是百度/夸克时缺 SHA1，流式中转时补算 |

### 路径 3：流式中转（跨平台主干）

- 原理：边下载边上传，数据流经内存不落盘；过程中实时计算目标盘所需哈希，命中秒传即终止，未命中继续流式上传。数据全程只流过一次。
- 实现：优先走 OpenList 的跨存储复制（fs/copy API）；特殊需求自研 httpx 流式管道。
- 特例：夸克→百度可「只拉前 256KB」补算 slice-MD5 后尝试秒传（轻量预检，是否实现按 PoC 结论定夺）。

### 路径 4：目标盘离线下载（零流量捷径）

- 原理：资源能解析出磁力 / HTTP 直链时，直接把任务丢给目标网盘的离线下载，家里电脑全程不出流量。
- 适用：夸克 / 百度 / 阿里都有离线下载能力（API 形态在 PoC 中验证）。

#### 3.2 九方向可行性矩阵

| 源 \ 目标 | 百度 | 夸克 | 阿里 |
|---|---|---|---|
| 百度 | 路径 1 直转 | 秒传尝试 → 流式 | 秒传尝试 → 流式 |
| 夸克 | 256KB 预检秒传 → 流式 | 路径 1 直转 | 秒传尝试 → 流式 |
| 阿里 | 流式 | 流式 | 路径 1 直转 |

## 四、总体架构（v2）

```
   小圈子用户（10~50 人，带密码访问）
          │ HTTPS
          ▼
   Cloudflare（免费版）+ 命名隧道 + CF Access 验证
          │ cloudflared 出站隧道（家里无需公网 IP）
          ▼
┌────────── 家里电脑 · Docker Compose ──────────┐
│                                               │
│  转存站 Web UI（自研：FastAPI + 轻前端）        │
│    ├ 链接解析：识别百度/夸克/阿里分享链接+提取码 │
│    ├ 编排引擎：直转 → 秒传 → 流式中转 → 离线    │
│    ├ 任务管理：SQLite + 线程池（低并发足够）     │
│    └ 分享生成：调目标盘接口返回新链接+提取码     │
│                                               │
│  OpenList（转存引擎底座）                      │
│    ├ 挂载：百度 / 夸克 / 阿里Open / 本地缓存    │
│    ├ 跨盘复制：流式中转，数据不落盘             │
│    ├ 离线下载：magnet/HTTP 丢给目标网盘         │
│    └ 直链下载：中转下载站（302 直链 / 代理）     │
│                                               │
│  2TB 缓存盘：热门文件缓存（LRU 清理）           │
└───────────────────────────────────────────────┘
```

### 4.1 组件选型与理由

| 组件 | 选型 | 理由 |
|---|---|---|
| 转存引擎 | OpenList（社区分叉，非 AList） | 三盘驱动、跨盘复制、离线下载、直链全是现成 API，自研量减半；AList 2025 年被售并加入默认遥测，不再使用 |
| 夸克操作 | QuarkPanTool 的 API 服务模式（默认 8007 端口） | 自带「转存并分享」等 RESTful 接口，比裸写 Cookie 请求稳 |
| 后端框架 | FastAPI + SQLite + 线程池 | 小圈子低并发用不上消息队列；少两个常驻组件，故障面更小 |
| 对外入口 | cloudflared 命名隧道 + CF Access | 免费、自带 HTTPS、免公网 IP、免备案 |
| 缓存 | 2TB 本地盘 + LRU 清理 | 热门文件二次下载不请求网盘 |

## 五、中转下载站

### 5.1 三种下载模式

| 模式 | 流量路径 | 速度 | 适用 |
|---|---|---|---|
| 302 直链（优先） | 用户 → 网盘 CDN，不经过家里 | 快，吃网盘 CDN 带宽 | 阿里 Open 等支持 302 的盘（夸克/百度防盗链需实测） |
| 本地缓存 | 用户 ← 家里电脑（2TB 热门缓存） | 家宽上行上限（4~6MB/s） | 热门与常用文件，二次下载不再请求网盘 |
| 代理中转（兜底） | 用户 → CF → 家里 → 网盘 CDN 回流 | 慢，双倍占用上行 | 以上都不适用时 |

### 5.2 带宽与限制

- 上海移动家宽上行普遍 30~50Mbps（300M 套餐约 30M、千兆套餐约 50M），即 4~6MB/s，这是「从家里下载」的物理天花板；可打客服电话确认具体上行，必要时加购上行提速包。
- Cloudflare Tunnel 免费不限速、自带 HTTPS；国内高峰期速度有波动（社区实测常见 2~6MB/s）。其 100MB 单请求体上传上限只影响「向网站上传文件」，不影响下载方向。
- 定位结论：中转下载 = 小圈子中小文件的高体验通道——非会员从百度下载几十 KB/s，走中转能到 MB/s 级；大文件优先 302 直链或网盘分享链接，别把它当 NAS 级下载站。

### 5.3 安全边界

- 命名隧道绑定自有域名（如 pan.fivor.cc），CF Access 加邮箱 OTP 或统一密码，杜绝陌生人扫到入口。
- 阿里云盘 token 严禁多 IP 频繁访问（会触发封号）→ 阿里盘在中转下载站只走 302 / 本地缓存，避免代理流量模式。
- OpenList 与转存站的管理后台只监听本机 / 内网，仅把下载路径暴露到隧道。

## 七、实施计划（阶段 0~5）

### 阶段 0：环境准备（约半天）

- [ ] 家里电脑安装 Docker Desktop 与 Docker Compose
- [ ] 域名（fivor.cc 子域，如 pan.fivor.cc）托管到 Cloudflare 并创建命名隧道

- [ ] 规划目录：/data/cache（缓存）、/data/openlist（配置）、/data/app（任务库）

验收：手机 4G 环境打开域名，弹出密码验证，通过后进入服务。

### 阶段 1：PoC 技术验证（1~2 天）

- [ ] Docker 部署 OpenList，挂载百度 / 夸克 / 阿里Open / 本地缓存四个存储
- [ ] 按第八节清单逐项验证并记录数据（速度、是否落盘、哈希字段、风控信号）

验收：产出验证报告，锁定哈希字段、直链模式与隧道实测速度等实现细节。

### 阶段 2：同平台直转 MVP（3~5 天）

- [ ] Web UI v0：单页输入链接 → 识别平台 → 提交转存 → 返回新分享链接 + 提取码
- [ ] 百度→百度：Cookie 方案，参考 BaiduPanFilesTransfers
- [ ] 夸克→夸克：QuarkPanTool API 服务模式，「转存 + 分享」一体完成
- [ ] 阿里→阿里：官方 OpenAPI / 分享转存接口
- [ ] SQLite 任务表：状态、进度、失败原因；同平台转存秒级，同步返回即可

验收：三类链接各自输入后 10 秒内返回可用分享链接。

### 阶段 3：跨平台中转（1~2 周）

- [ ] 编排引擎：按「直转 → 秒传尝试 → 流式中转 → 离线下载」优先级调度
- [ ] 流式中转优先走 OpenList fs/copy，特殊需求自研 httpx 流式管道；过程实时计算目标盘所需哈希，命中秒传即终止
- [ ] 夸克→百度的「只拉前 256KB 预检秒传」按 PoC 结论决定实现与否
- [ ] 异步任务 + 前端轮询进度；失败自动重试与降级

验收：9 个转存方向全部可用，记录各方向平均耗时与秒传命中率。

### 阶段 4：中转下载站（2~4 天）

- [ ] 开放 OpenList 直链：302 直链优先、本地缓存次之、代理兜底
- [ ] 2TB 缓存策略：LRU 淘汰、单文件体积上限、按任务保留天数
- [ ] CF Access 限流 + 下载日志

验收：小圈子成员外网实测三种模式下载速度并留存记录。

### 阶段 5：稳定性与账号运维（持续）

- [ ] Cookie/Token 定时巡检，失效即飞书 bot 告警（沿用现有通知链路）
- [ ] 本地「账号续期」小页面：Cookie 失效时手动扫码 / 粘贴新值写回
- [ ] 全链路限频与随机延迟；操作日志；缓存清理定时任务；SQLite 每日备份

验收：Cookie 失效 10 分钟内收到飞书告警。

## 九、风险与应对

| 风险 | 应对 |
|---|---|
| 跨平台纯秒传不可行 | 流式中转为主、秒传为加速器（第三节） |
| 家宽上行仅 4~6MB/s | 中转下载定位小圈子中小文件；大文件走 302 / 网盘链接 |
| CF Tunnel 国内高峰波动 | 命名隧道 + 自有域名；重要场景提供网盘链接兜底 |
| 夸克接口变动 | Docker 固定版本，跟随上游项目更新 |
| 阿里 token 多 IP 风控（封号） | 仅自用账号授权；下载站对阿里只走 302 / 缓存 |
| Cookie / Token 过期 | 定时巡检 + 飞书告警 + 本地续期页面 |
| 百度频控（分享约 300 条/日、转存频率限制） | 会员已缓解；限频、随机间隔 |
| 秒传命中率不确定（冷门资源为 0） | 自动 fallback 流式中转 |
| 2TB 容量有限 | LRU 缓存、限制单任务体积、转存后清理 |
| 批量操作触发风控 / 封号 | 多账号冗余、限频、避免短时间海量操作 |

## 十、合规说明

- 仅小圈子自用、不公开传播、不破解会员、不绕过付费——全程只使用网盘官方已有能力（转存 / 秒传 / 离线下载），风险极低。
- 入口加密码（CF Access），不留公开注册；操作日志仅本地留存。
- 不在圈子内广泛扩散明显侵权 / 盗版资源，保持在自用边界内。

本机 C~~G 五个分区全是 400~~500 GB 级别，无单块 2TB 盘。用户决定直接用 G 盘目录作缓存。**目录三件套已创建（2026-09-15）**：

compose 挂载时用 `G:\Netdisk\data\cache:/opt/openlist/data/cache` 之类的本机绝对路径映射即可（Docker Desktop 支持直接挂 G 盘路径）。

### 3. ⚠️ 代理隔离：网盘 API 严禁过代理（✅ 用户确认按此执行）

本机存在**三层代理设施**：

- 环境变量 `HTTP_PROXY=http://127.0.0.1:51685`
- 自启项 "Hermes Gateway"（PowerShell 隐藏窗口方式）
- 容器 warp-proxy、privoxy 常驻

方案 5.3 明确"阿里 token 严禁多 IP 频繁访问（封号）"，百度/夸克同理忌讳 IP 跳变。写代码时必须立规矩：

- compose 里**不给** openlist / app 容器传任何 `HTTP*_PROXY` 环境变量；
- PoC 脚本 `requests`/`httpx` 显式 `trust_env=False`（httpx）或 `session.trust_env=False`（requests）；
- cloudflared 服务本身出站 CF 边缘没问题（它只连 CF），不用动。

### 4. 隧道 ingress 与 CF Access（待用户网页操作，指引见第五节）

cloudflared 是 **token 远程管理模式**——没有本地 config.yml，路由规则全在 Cloudflare Zero Trust 控制台。需确认：

- Public Hostname 已建：`your-domain.example`（或实际子域）→ `http://localhost:<应用端口>`；

## 五、CF 网页操作指引（用户在 Cloudflare Dashboard 执行）

现有隧道（token 模式，ID `3f7cb064-e8b7-44a0-9b22-7b15870539c7`）的 ingress 与 Access 均需在网页端配置：

**A. 配置 Public Hostname（ingress 路由）**

1. 打开 <https://one.dash.cloudflare.com/> → **Networks → Tunnels**；
2. 找到现有隧道（ID 与上文一致的那个）→ **Edit → Public Hostname 标签页**；
3. 新增一条 Public Hostname：
   - Subdomain：`pan`（Domain 下拉选 `fivor.dev`，即 `your-domain.example`）
   - Service Type：`HTTP`，URL：`localhost:8100`（转存站 FastAPI 端口，与端口规划表一致）
   - 如需直接访问 OpenList，再加一条：Subdomain `openlist` → Service `HTTP` → `localhost:5244`（可选，建议只暴露转存站，OpenList 后台不对外，见方案 5.3）
4. 保存后 cloudflared 会自动热加载路由，无需重启服务。

**B. 开启 CF Access 密码验证**

1. 同一控制台 → **Access → Applications → Add an application → Self-hosted**；
2. Application domain：填 `your-domain.example`（对应上面的子域）；
3. Authentication：按方案加「邮箱 OTP」或「统一密码」（One-time PIN 最简单：Add policy → Action=Allow → Include → Emails 填小圈子成员邮箱；登录时收验证码）；
4. 保存后用手机 4G（非家里 WiFi）打开 `https://your-domain.example` 验收：应先弹 Access 验证页，通过后才到转存站。

**C. 验收（照方案阶段 0 标准）**  
手机 4G 环境打开域名 → 弹出密码/验证码验证 → 通过后进入服务。

# 本机高速下载中转站 · 可行性分析

> 2026-09-17 · 状态：待确认，未开工

## 需求复述

用户提交网盘分享链接 → 服务器（本机，有夸克/百度会员）用会员速度把文件下载到本机 → 生成本站下载链接 → 用户以远超非会员限速的速度下载。本机成为高速下载中转站。

## 实测数据（本机，2026-09-17）

| 项目 | 实测值 | 含义 |
|---|---|---|
| 家宽下行 | 146.28 Mbps ≈ 18 MB/s | 源盘→本机的下载上限（会员速度另计） |
| **家宽上行** | **80.49 Mbps ≈ 10 MB/s** | **用户从本机下载的速度天花板** |
| G 盘剩余 | 404 GB | 本机缓存容量上限 |
| OpenList Local 驱动 | 存在 ✓ | 本机可直接作为存储挂载 |

## 速度账（诚实的部分）

会员加速只作用于**服务器下载侧**（源盘→本机）。用户拿到的下载速度 = min(家宽上行, 隧道吞吐, 用户自己的下行)：

| 对比 | 速度 | 4GB 文件耗时 |
|---|---|---|
| 百度非会员直下 | ~0.1-0.3 MB/s | 4-11 小时 |
| 夸克非会员直下 | ~0.5-1 MB/s | 1-2 小时 |
| **本机中转（上行 10MB/s）** | **~10 MB/s** | **~7 分钟** |

结论：对没有会员的用户是 **10~100 倍提升**，"高速"名副其实；但上限是家宽上行的 10MB/s，不是会员级速度。多人同时下载会均分上行（需并发限流）。

## 推荐架构：新增「本机」第五目标平台（复用现有全套机制）

```
用户粘贴链接 → 选「本机高速下载」
  → 源盘 save（现有适配器）
  → OpenList fs/copy：源盘挂载 → /local/转存（流式落盘 G:\Netdisk\data\downloads）
  → 本地定位（文件已在磁盘）
  → 生成下载链接 https://your-domain.example/dl/<任务ID>/<文件名>?k=<签名>
```

- OpenList 挂载 Local 驱动到 `/local`，跨平台中转机制**原样复用**（含进度映射、失败转译、幂等预检）
- 本机永不作为源平台（无分享能力），仅作目标
- 下载端点 `/dl/...`：FastAPI FileResponse 流式输出，支持 Range 断点续传
- 链接鉴权：HMAC 签名 token（按任务派生、可带有效期），链接不可猜测、不可遍历
- 缓存管理：TTL 自动清理（默认建议 7 天）+ 容量软上限（建议 300GB）+ 管理员手动删除
- 并发限流：同时下载流数上限（建议 3），保护上行不被打满
- 重复提交同一分享 → 幂等（现有预检机制直接复用，秒出链接）

### 为什么不用「302 直链」方案（把网盘直链直接甩给用户）

1. UC 驱动在 OpenList 里是 `OnlyProxy: true`——直链方案对 UC 直接不可用；
2. 网盘直链有时效（百度约 8 小时）且外泄后无法撤回；
3. 直链外流正是网盘风控重点打击的行为，**账号风险显著更高**；
4. 通过本机代理（方案 A）流量特征 = 正常会员下载，风险可控。

## 风险与边界

| 风险 | 评估 |
|---|---|
| Cloudflare 免费隧道 | 100MB 限制只针对**上传**请求体，下载（流式响应）不受限；但免费版 TOS 禁止视频分发，大文件下载属灰色地带，一般容忍、需留意。后续可评估公网 IPv6 直连绕开 CF |
| 账号风控 | 中低：流量特征=会员账号正常下载自己的文件；避免直链外流方案后风险可控 |
| 磁盘 | 404GB 上限 → TTL + 软上限 + 管理员删除三道闸 |
| 合规 | 与现有一致：链接仅小圈子可见（站点口令/CF Access 上线前是总闸）、不公开入口、不扩散侵权内容 |
| 电脑常开 | 已确认不睡眠 ✓ |

## 工作量估算

后端 ~250 行（local 适配器 + /dl 流式端点 + 缓存清理线程 + 配置）+ 前端 ~30 行（目标芯片/结果区/磁盘占用）+ 测试 ~10 用例。一个迭代内完成，含真实验证。
